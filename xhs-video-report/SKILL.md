# 小红书视频 → HTML 图文学习报告

## 核心认知

科普视频的信息分布：**口播占 70-80%，画面只占 20-30%**。
所以这套流程的灵魂是「把视频变成一篇可读的稿子」——转录是主菜，抽帧是配菜。
不要试图逐帧"看懂"视频，那是低效且昂贵的。

**输出物是 HTML，不是 Markdown。** 报告定位是"可读、可分享、可打印"的图文页面，
不是塞进知识库的原始笔记。模板见 `references/report-template.html`。

## 为什么不用 yt-dlp

yt-dlp 对小红书成功率仅约 10%（标准抓取器），移动优先 URL + 签名校验导致大量失败。
本 skill 走 **bsk 驱动用户已登录的真实浏览器**，登录态天然可用，规避反爬。
**不需要用户提供任何账号密码** —— 只借用其已登录的浏览器窗口。

## 前置依赖

- `imageio-ffmpeg` — 提供 aarch64 原生 ffmpeg 二进制
- `mlx-whisper` — Apple Silicon GPU 加速转录（M4 上 10 分钟音频约几十秒）
- `bsk` — 通常位于 `~/.local/bin/bsk`，需浏览器扩展已连接（`bsk doctor` 检查）

环境体检：`$PY scripts/selfcheck.py`，全绿才能跑通。

**网络坑（脚本已自动处理，但要懂原理）**——2026-09-05 实测踩过：
1. 代理环境下 huggingface.co 返回 502 → 脚本检测到代理后自动切 `HF_ENDPOINT=https://hf-mirror.com`
2. 镜像站下 Xet 存储后端 401 → 脚本自动设 `HF_HUB_DISABLE_XET=1` 回退传统下载
3. imageio 的 ffmpeg 二进制带平台后缀不叫 `ffmpeg`，而 mlx-whisper 硬编码调 `ffmpeg` 命令 → 脚本自动建同名软链并加入 PATH

**转录质量实测**：中文科普内容准确率约 97%（whisper-large-v3-turbo），仅个别缩写和同音字错，够用。

## 工作流

### 第 1 步：取直链与元数据（风险最高，先探测）

```bash
PY=<python 解释器绝对路径>
$PY scripts/fetch_meta.py "<小红书笔记URL>" --out /tmp/xhs_meta.json
```

输出 `ok: true` 且 `video` 非空才算通。若失败：
- `videos` 里有 `blob:` 开头 → 视频走 MSE 播放，需改用录屏或抓 m3u8（见"已知限制"）
- `videos` 为空 → 页面未加载完，加 `--wait 10` 重试
- 报 session 错 → 跑 `bsk doctor` 确认扩展在线

### 第 2 步：下载 + 抽音频 + 转录 + 抽帧

```bash
$PY scripts/media.py --meta /tmp/xhs_meta.json --workdir /tmp/xhs_work
```

产物：`audio.wav`、`transcript.txt`、`frames/*.jpg`（自适应 8-12 帧）、`meta.json`。
首次运行会下载 whisper 模型（约 1.5GB），耐心等。

### 第 3 步：生成 HTML 报告（Agent 本人做，不要脚本化）

1. `cp references/report-template.html <目标路径>.html`
2. 读 `transcript.txt`；**必须用 Read 工具真的打开关键帧看内容** —— 只看文字不看图 = 丢掉那 20-30% 的画面信息
3. 替换模板占位符，产出完整报告

### 第 4 步：归档

```
<vault 或 目标目录>/AI技术/视频学习报告/2026-09-05-英文短名.html
<vault 或 目标目录>/AI技术/视频学习报告/frames/f02_语义.jpg
```

约定：
- **文件名用 ASCII**（HTML 引用图片路径 + 日后分享链接都更安全），中文标题放在 HTML 内部
- 帧文件也用 ASCII + 语义命名（`f02_tips.jpg`、`f09_fde.jpg`），一眼看得出是哪一幕
- 关键帧**只挑真正有信息量的 3-5 张**复制过去，其余留在 /tmp
- HTML 用相对路径 `frames/xxx.jpg` 引用，整目录可整体拷贝/分享

## 报告结构（双层，对应模板各区块）

| 区块 | 要求 |
|---|---|
| **速览卡** | 一句话结论 + 三条核心点 + 值不值得细看（星级）+ 一个行动 |
| 1 问题重述 | 这条视频到底在解决什么问题 |
| 2 可复用方法 | 招式层，能直接抄进工作流的操作 |
| 3 心法/观点 | 金句 + 提炼（用 `.quote` 样式） |
| 4 反直觉点 | **最值钱的一节**，不是复述内容 |
| 5 与我何干 | 结合用户画像与在推进的事，写具体落点 |
| 6 行动清单 | 带链接/文件名的可执行项 |
| 元数据与质量说明 | 转录字数、ASR 纠错项、引用帧数、遗留待确认 |

## 写作要求

- **一句话结论必须是一句话**，且是最反直觉或最有用的那个点，不是"介绍了XX"这种废话
- **核心三点要有信息增量**，别写成目录
- **值不值得细看**要敢下判断，这决定了用户要不要回看原视频
- 深度笔记部分**用自己的逻辑重组**，不要按视频时间线流水账
- 图注要说明"这张图补充了什么"，不是"如图所示"
- **ASR 纠错是必做项**：专有名词几乎必错（实测 DeepSeek→Deep C Carnics、Markdown→MacDone、
  Anthropic→Atheropic、Vibe Coding→webcoding）。按上下文还原，并在文末「质量说明」列出纠错项
- **「与我何干」要有具体落点**：引用用户真正在做的项目名称/方向，不写"对你的工作有帮助"这类空话
- **画面有但口播没念的信息**（链接、工具名）若无法确认，如实标注"待回看确认"，不要编造
- **口播提到的资源要反查确认**：视频常说"GitHub 上很火那个库"却不给地址，用 WebSearch 反查
  （实测把"11万 star 设计风格库"查实为 VoltAgent/awesome-design-md），比含糊写"视频里有"有用得多

## 已知限制与关键机制（2026-09-05 真实环境实测）

1. **xsec_token 是生死线**：笔记 URL 必须带 `?xsec_token=...`，否则显示「请打开App扫码查看」。
   用户分享链接自带 token；从列表页抓链接时**千万别把 query 丢掉**。
2. **blob: URL 视频**：部分笔记走 MSE 播放，DOM 里只有 `blob:` 伪协议。
   兜底：QuickTime 录屏，或 `ffmpeg -f avfoundation`。
3. **需要登录态**：bsk 依赖浏览器扩展在线 + 用户已登录小红书网页版。
4. **无口播视频 → Whisper 幻觉**：纯 BGM/静音会输出整篇 "Thank you."。
   写报告前先看 transcript：极短（<50 字）或高度重复 → 判定低口播，报告以画面 + 笔记文案为主。
5. **长视频成本**：超过 20 分钟转录/抽帧成本显著上升，先问用户是否只要速览卡。
6. **批量处理**：一次别超过 5 条，避免 session 超时和 token 爆炸。
