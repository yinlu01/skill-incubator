# 费曼自测卡

用「反过来考」的方式检验学习效果：输入是已学的笔记/卡片/章节，输出是一组自测问答卡。核心假设——**能用自己的话讲清楚才算真会**。本 skill 的价值不在生成卡片本身，而在逼用户**先输出、再对照**，暴露「以为会了」和「真会了」之间的差距。

## 输入源（按优先级）

1. 用户指定的 Obsidian 笔记/卡片（Vault：`~/Obsidian/`，含 AI 技术卡片体系）
2. 用户当前学习进度对应的主题（读取用户指定的学习规划 JSON，按当天日期定位当日 topic；路径每次由用户提供，或设置环境变量 `STUDY_PLAN_JSON`，无需硬编码）
3. 近期微信读书划线（可调用 `weread-skills` 拉取）
4. 用户直接粘贴的内容

用户只说「考考我」时：读学习计划定位当天主题，若主题过窄（如纯实操日），取本周已学知识点合集出卡，并告知选题依据。

## 工作流（严格顺序）

1. **读材料**：完整理解笔记内容，识别核心概念、机制原理、适用场景、易混概念对。
2. **生成卡片组**：按下方四层模型出 5-8 张卡，宁少勿滥，只考核心。组内四层都要有，辨析层必考用户易混的概念对（如 Agent vs Workflow、RAG vs 微调、System Prompt vs User Prompt）。
3. **发起自测**：只展示问题（含层次标签），明确提示「先别看答案，口头或打字作答」。**绝不在出题阶段就展示答案。**
4. **逐题对照**：收到用户作答后再展示参考答案，对照点评：答对 / 模糊 / 答错，一句点评指出差距。
5. **出结果**：全部答完后汇总——各层掌握度、总评、错题清单。
6. **间隔重复建议**：答错的卡 3 天后再测，模糊的 7 天后再测，答对的 14 天后可并入大复习。
7. **回填建议**：把「模糊/答错」卡片对应的知识点列成待复习清单，建议用户写回原笔记（或问用户要不要直接生成回填段落到 Obsidian 文件）。

## 四层卡片模型

| 层 | 问题形态 | 检验什么 | 示例 |
|---|---|---|---|
| 概念层 | X 是什么？ | 定义复述 | ReAct 是什么？ |
| 机制层 | 为什么 X 这样设计/运作？ | 原理理解 | 为什么 System Prompt 要放角色、约束、输出格式？ |
| 应用层 | 什么场景用 X？怎么用？ | 迁移能力 | 客服 Agent 的提示系统该怎么分层？ |
| 辨析层 | X 和 Y 有什么区别？ | 易混对比 | RAG 和微调，什么时候选哪个？ |

## 卡片格式

```markdown
**Q3（机制层）**：为什么 ReAct 要让模型先输出 Thought 再输出 Action？

（等待用户作答）

**参考答案**：Thought 步骤强迫模型把推理链显式化——先说清楚"我为什么需要这个工具"，再发起调用。一方面提升工具选择的准确性（相当于 chain-of-thought），另一方面让每一步决策可追溯、可调试，出错时能定位是推理错了还是工具结果错了。
**易踩坑**：把它说成"为了显得像人在思考"——收益在准确性与可解释性，不是拟人化。
```

参考答案要求：3-5 句、大白话复述、不照抄笔记原文——费曼法的核心就是**换述**。若笔记原文已经足够口语化，也要重组语序而非原文粘贴。

## 约定

- 每组 5-8 张，用户可指定「只要辨析层」等子集。
- 点评对事不对人：指出差距在哪，不评价用户能力。
- 答案阶段才展示答案，任何情况下不要一次性把问答全吐出来。
- 若用户答「不知道」，按答错处理，参考答案讲得更细一点。
- 输出保持 Markdown，可整段复制到 Obsidian。
